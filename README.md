# Симулятор тестовой станции умных устройств

Учебный проект под вакансию Python-разработчика в SberDevices (команда Chamber).
Цель — своими руками пройти путь от "эмулированного устройства" до полноценной
тестовой станции с API, интеграцией с MES, логами в базе и дашбордом.

## Шаг 1 — Эмулятор устройства (готово)

Папка `dut\_emulator/` содержит:

* **`emulator.py`** — TCP-сервер на порту 9000, который ведёт себя как
реальное умное устройство: понимает команды `PING`, `GET\_STATUS`,
`SET\_VOLUME <0-100>`,`STOP` и с некоторой вероятностью специально "капризничает":
отвечает с задержкой, шлёт ошибку "device busy" или вообще рвёт соединение.
Это сделано намеренно — на реальной станции с железом такие ситуации
норма, и именно с ними придётся уметь работать на следующем шаге.
* **`manual\_client.py`** — простой скрипт для ручной проверки: подключается
к эмулятору и по очереди шлёт несколько команд, печатая ответы. Не часть
тестовой станции, просто инструмент для глаз.

### Как запустить самому

Нужен только Python 3.10+ (без сторонних библиотек).

Терминал 1:

```bash
cd dut\_emulator
python3 emulator.py
```

Терминал 2:

```bash
cd dut\_emulator
python3 manual\_client.py
```

Вы должны увидеть в терминале 2 примерно такое:

```
>>> Отправляю: PING
<<< Ответ: {"result": "PONG"}
>>> Отправляю: GET\_STATUS
<<< Ответ: {"result": "ok", "firmware": "1.4.2", "uptime\_sec": 3}
...
```

А в терминале 1 — лог того, какие команды пришли.

### Что стоит сделать самому, прежде чем идти дальше

Чтобы этот шаг реально "усвоился", а не просто был скопирован:

1. Запустите оба скрипта и посмотрите на реальный обмен командами вживую.
2. Покрутите вероятности `PROB\_SLOW\_RESPONSE`, `PROB\_BUSY\_ERROR`,
`PROB\_CONNECTION\_DROP` в `emulator.py` — например, поставьте
`PROB\_CONNECTION\_DROP = 0.5` и посмотрите, как клиент падает с ошибкой.
Это важно: на следующем шаге мы будем именно от таких обрывов защищаться.
3. Добавьте одну новую команду самостоятельно, например `REBOOT`, которая
отвечает `{"result": "ok", "message": "rebooting"}`, но перед ответом
"спит" 2 секунды. Если получится без подсказок — двигаемся дальше.
4. Закоммитьте это в свой git-репозиторий (см. ниже).
